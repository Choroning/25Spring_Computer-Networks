## 1. 전달(Delivery)

네트워크 계층은 전달을 관리한다. 패킷을 최종 목적지까지 전달하는 것은 **직접 전달**과 **간접 전달**이라는 두 가지 방법을 사용하여 수행된다.

### 1.1 직접 전달

**직접 전달(Direct Delivery)** 은 목적지 호스트가 송신자와 **동일한 물리적 네트워크**에 있을 때 발생한다:

```text
         Link
Host A ----------- Host B
    \              /
     \  Switch    /
      +---------+
```

*그림 1. 같은 네트워크에 있는 두 호스트 사이의 직접 전달*

주요 특징:
- 출발지와 목적지가 **동일한 네트워크**에 있을 때 수행된다.
- 출발지와 목적지가 다른 네트워크에 있으면 **마지막 라우터와 목적지 호스트** 사이에서 수행된다.
- 송신자는 목적지 주소에서 **네트워크 주소(netid)** 를 추출하여 자신의 네트워크 주소와 비교한다.
- 일치하면 직접 전달을 수행한다.

### 1.2 간접 전달

**간접 전달(Indirect Delivery)** 은 목적지 호스트가 **다른 네트워크**에 있을 때 발생한다:

```text
  A                                              B
[Host] --- Switch --- Router --- Router --- Switch --- [Host]
  |                     |          |                    |
  +-- Indirect Delivery +          +-- Direct Delivery -+
```

*그림 2. 라우터를 거치는 간접 전달과 마지막 직접 전달*

주요 특징:
- 목적지가 송신자와 **동일한 네트워크에 있지 않다**.
- 패킷이 하나 이상의 **라우터**를 거친다.
- 다음 홉 IP 주소를 찾기 위해 **라우팅 테이블**을 사용한다.
- 마지막 전달은 항상 직접 전달이다.

> **핵심:** 간접 전달에서 송신자와 중간 라우터는 패킷을 다음 라우터로 전달한다. 최종 전달(마지막 라우터에서 목적지 호스트로)만 직접 전달이다.

## 2. 포워딩(Forwarding)

**포워딩**이란 패킷을 목적지까지의 경로에 올려놓는 것을 의미한다. 포워딩을 수행하려면 호스트나 라우터에 **라우팅 테이블**이 있어야 한다.

### 2.1 포워딩 기법

라우팅 테이블의 크기를 관리 가능한 수준으로 유지하거나 특수한 요구를 처리하는 네 가지 포워딩 기법이 있다:

**1. 다음 홉 방식(Next-Hop Method):**
- 라우팅 테이블에 완전한 경로 대신 **다음 홉**의 주소만 저장한다.
- 테이블 크기를 줄이고 포워딩 과정을 단순화한다.

```text
Route-Based Table:              Next-Hop Table:
+------+------------------+     +------+---------+
| Dest | Route             |    | Dest | Next Hop|
+------+------------------+     +------+---------+
|  B   | R1, R2, Host B   |    |  B   |   R1    |
+------+------------------+     +------+---------+
```

*그림 3. 경로 기반 테이블과 다음 홉 테이블*

**2. 네트워크 특정 방식(Network-Specific Method):**
- **모든 목적지 호스트**에 대한 항목 대신 **목적지 네트워크** 하나에 대한 항목만 사용한다.
- 라우팅 테이블 크기를 획기적으로 줄인다.

```text
Host-Specific Table:            Network-Specific Table:
+------+---------+              +------+---------+
| Dest | Next Hop|              | Dest | Next Hop|
+------+---------+              +------+---------+
|  A   |   R1    |              |  N2  |   R1    |
|  B   |   R1    |              +------+---------+
|  C   |   R1    |
|  D   |   R1    |
+------+---------+
```

*그림 4. 호스트 특정 테이블과 네트워크 특정 테이블*

**3. 호스트 특정 방식(Host-Specific Method):**
- 라우팅 테이블에 **특정 목적지 호스트**에 대한 항목을 포함한다.
- 특정 호스트에 대한 특별한 경로가 필요할 때 사용한다(예: 보안이나 특수 처리).
- 네트워크 특정 방식의 역이다.

**4. 기본 경로 방식(Default Method):**
- 모든 네트워크를 나열하는 대신 단일 **기본 항목(0.0.0.0)** 을 사용한다.
- 특정 항목과 일치하지 않는 패킷은 기본 라우터로 전송된다.

### 2.2 클래스 기반 주소 지정에서의 포워딩

클래스 기반 주소 지정에서 라우터는 세 개의 테이블(Class A, B, C 각각 하나씩)을 가진다.

각 라우팅 테이블 항목은 최소 세 개의 열을 가진다:

| 열 | 설명 |
|--------|-------------|
| Network Address | 목적지 호스트가 위치한 네트워크 |
| Next-Hop Address | 간접 전달을 위해 패킷이 전달되어야 하는 라우터 |
| Interface Number | 나가는 포트 (m0, m1 등) |

*표 1. 클래스 기반 라우팅 테이블 항목의 최소 열*

**포워딩 과정 (클래스 기반):**
1. 패킷 헤더에서 목적지 IP 주소를 추출한다.
2. 처음 몇 비트로 클래스(A, B, C)를 결정한다.
3. 클래스별 기본 마스크를 적용하여 네트워크 주소를 추출한다.
4. 해당 클래스의 테이블에서 네트워크 주소를 검색한다.
5. 발견되면 지정된 인터페이스를 통해 다음 홉 주소로 포워딩한다.
6. 발견되지 않으면 기본 항목을 사용한다.

### 2.3 클래스리스 주소 지정(CIDR)에서의 포워딩

클래스리스 주소 지정에서는 마스크와 함께 네트워크 주소(접두사)를 포함하는 **하나의 테이블**이 있다:

```text
+------------------+------+-----------+-----------+
| Network/Prefix   | Mask | Next Hop  | Interface |
+------------------+------+-----------+-----------+
| 192.168.1.0/24   | /24  | R1        | m0        |
| 10.0.0.0/8       | /8   | R2        | m1        |
| 0.0.0.0/0        | /0   | R3        | m2        |  <-- Default
+------------------+------+-----------+-----------+
```

*그림 5. 마스크와 기본 경로를 포함한 클래스리스 포워딩 테이블*

**포워딩 과정 (클래스리스):**
1. 목적지 주소를 추출한다.
2. 테이블의 각 항목에 대해 그 항목의 마스크를 목적지 주소에 적용(AND 연산)한다.
3. 결과가 그 항목의 네트워크 주소와 일치하면 후보 항목이 된다.
4. **최장 접두사 매칭**을 적용하여 최적의 경로를 선택한다.
5. 해당하는 다음 홉으로 포워딩한다.

## 3. 라우팅 테이블 구조

### 3.1 라우팅 테이블 열

일반적인 라우팅 테이블은 다음을 포함한다:

| 열 | 설명 |
|--------|-------------|
| Destination Network | 접두사 길이를 포함한 네트워크 주소 |
| Subnet Mask | 목적지 네트워크에 대한 마스크 |
| Next Hop | 다음 라우터의 IP 주소 (또는 "directly connected") |
| Interface | 나가는 인터페이스 식별자 |
| Metric | 목적지까지의 비용/거리 |
| Flags | 경로 유형 표시 (U=up, G=gateway, H=host 등) |

*표 2. 일반적인 라우팅 테이블의 열*

### 3.2 주소 집약

주소 집약(슈퍼넷팅)은 라우팅 테이블 항목을 줄인다:

```text
Before aggregation:          After aggregation:
192.168.0.0/24  --> R1       192.168.0.0/22 --> R1
192.168.1.0/24  --> R1       (하나의 항목이 네 개를 대체)
192.168.2.0/24  --> R1
192.168.3.0/24  --> R1
```

*그림 6. 네 개의 /24 항목을 하나의 /22 항목으로 집약하기 전과 후*

> **핵심:** 주소 집약은 네트워크들이 연속적이고, 합친 범위가 하나의 CIDR 블록을 이루며, 동일한 다음 홉을 공유할 때만 작동한다. 이는 인터넷 확장성의 핵심이다.

### 3.3 최장 접두사 매칭

여러 라우팅 테이블 항목이 목적지 주소와 일치할 때, **가장 긴 접두사**(가장 구체적인 매칭)를 가진 항목이 선택된다:

```text
Table:
  192.168.0.0/16   --> R1
  192.168.1.0/24   --> R2
  192.168.1.128/25 --> R3

For destination 192.168.1.200:
  /16 matches (192.168.x.x)     --> R1
  /24 matches (192.168.1.x)     --> R2
  /25 matches (192.168.1.128+)  --> R3  <-- 선택됨 (최장 접두사)
```

> **핵심:** 최장 접두사 매칭은 가장 구체적인 경로가 사용되도록 보장하여, 주소 집약과 특정 예외 경로가 공존할 수 있게 한다.

## 4. 부록

### 4.1 예제: 클래스 기반 포워딩

목적지 IP 주소 192.168.5.100이 주어진 경우:

1. 처음 3비트가 `110`이므로 Class C이다.
2. 기본 마스크는 255.255.255.0(/24)이다.
3. 네트워크 주소는 192.168.5.0이다.
4. Class C 라우팅 테이블에서 192.168.5.0을 검색한다.
5. 발견되면 지시된 다음 홉으로 포워딩한다.
6. 발견되지 않으면 기본 경로를 사용한다.

### 4.2 예제: 클래스리스 포워딩

목적지 IP 주소 10.1.2.100과 다음 라우팅 테이블이 주어진 경우:

| Network | Mask | Next Hop |
|---------|------|----------|
| 10.1.0.0 | /16 | R1 |
| 10.1.2.0 | /24 | R2 |
| 0.0.0.0 | /0 | R3 |

*표 3. 클래스리스 포워딩 예제의 라우팅 테이블*

1. 10.1.2.100 AND /16 = 10.1.0.0 --> 일치 (R1)
2. 10.1.2.100 AND /24 = 10.1.2.0 --> 일치 (R2)
3. 10.1.2.100 AND /0 = 0.0.0.0 --> 일치 (R3)
4. 최장 접두사 매칭에 따라 /24 항목을 선택하여 **R2**로 포워딩한다.

### 4.3 실제 라우팅 테이블 (Linux)

```console
$ ip route show
default via 192.168.1.1 dev eth0
10.0.0.0/8 via 10.0.0.1 dev eth1
192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.100
```

## 요약

| 개념 | 핵심 요약 |
|---------|-----------|
| 직접 전달 | 출발지와 목적지가 동일한 네트워크에 있을 때 수행되며, 마지막 홉의 전달은 항상 직접 전달이다. |
| 간접 전달 | 패킷이 라우터를 거치며, 다음 홉을 찾기 위해 라우팅 테이블을 사용한다. |
| 다음 홉 방식 | 완전한 경로가 아니라 다음 라우터의 주소만 저장한다. |
| 네트워크 특정 | 호스트마다가 아니라 네트워크마다 항목을 하나씩 둔다. |
| 기본 경로 | 테이블에 없는 목적지를 위한 포괄 항목(0.0.0.0/0)이다. |
| 클래스 기반 포워딩 | 클래스마다 별도의 테이블을 두고, 클래스 기본 마스크로 netid를 추출한다. |
| 클래스리스 포워딩 | 접두사와 마스크를 담은 단일 테이블을 두고, AND 연산으로 매칭한다. |
| 최장 접두사 매칭 | 일치하는 항목 중 가장 구체적인(접두사가 가장 긴) 항목이 우선한다. |
| 주소 집약 | 연속된 네트워크를 결합하여 테이블 크기를 줄인다. |

## 점검 문제

1. **직접 전달과 간접 전달:** 호스트 192.168.10.37/26이 목적지 192.168.10.70과 192.168.10.12로 각각 패킷을 보낸다. 각 경우가 직접 전달인지 간접 전달인지 판정하라.

   <details>
   <summary>정답</summary>

   /26의 마스크는 255.255.255.192이다. 37 AND 192 = 0이므로 송신자의 네트워크 주소는 192.168.10.0이다. 70 AND 192 = 64이므로 192.168.10.70의 네트워크 주소는 192.168.10.64이고, 송신자의 네트워크와 다르므로 간접 전달이다(기본 라우터로 보낸다). 12 AND 192 = 0이므로 192.168.10.12는 같은 네트워크에 있어 직접 전달이다.

   </details>

2. **최장 접두사 매칭:** 130.40.0.0/16은 R1, 130.40.32.0/19는 R2, 130.40.36.0/22는 R3, 0.0.0.0/0은 R4로 보내는 라우팅 테이블이 있다. 목적지 (a) 130.40.38.5 (b) 130.40.50.1 (c) 130.41.0.1의 다음 홉을 구하라.

   <details>
   <summary>정답</summary>

   (a) 세 번째 옥텟 38 = 00100110을 /19 마스크의 세 번째 옥텟 224와 AND하면 32이고, /22 마스크의 세 번째 옥텟 252와 AND하면 36이다. 따라서 네 항목이 모두 일치하고, 접두사가 가장 긴 /22 항목의 R3를 선택한다. (b) 50 AND 224 = 32이므로 /19 항목은 일치하지만, 50 AND 252 = 48이므로 /22 항목은 일치하지 않는다. 따라서 R2이다. (c) 130.41.0.1 AND 255.255.0.0 = 130.41.0.0은 130.40.0.0과 다르므로 기본 경로만 일치하여 R4이다.

3. **주소 집약과 예외 경로:** 라우터가 172.20.16.0/24부터 172.20.23.0/24까지 8개 네트워크를 모두 R1로 보낸다. 이 항목들을 하나로 집약하라. 이 중 172.20.20.0/24만 R2로 보내야 한다면 테이블을 어떻게 구성하는가?

   <details>
   <summary>정답</summary>

   세 번째 옥텟 16\~23은 이진수로 00010000\~00010111이며 앞의 5비트 00010이 같다. 공통 접두사는 16 + 5 = 21비트이고 16이 8의 배수이므로, 다음 홉이 R1인 172.20.16.0/21 항목 하나로 집약한다. 예외를 처리하려면 다음 홉이 R2인 172.20.20.0/24 항목을 추가한다. 172.20.20.x로 가는 패킷은 두 항목에 모두 일치하지만 최장 접두사 매칭에 따라 /24 항목의 R2로 가고, 나머지 일곱 네트워크로 가는 패킷은 /21 항목의 R1로 간다.

   </details>
